## Content: Reasons for choosing Firebase

My partner(Annabella) and I wanted to create a wishing Simulator where you can pull for different characters. While pulling, we wanted to create an animation and have it save your progress as you obtain more characters. Annabella chose to use Animate.JS to work on the front end of the website, while I decided to study [Firebase](https://firebase.google.com/) to make the back end of the website that saves the characters you collected. Another reason why I chose to use Firebase is that I like to challenge myself, and Firebase was one of the more challenging tools you can study. 

### How I "Tinkered" with Firebase

So far, I mostly studied the possibilities with Firebase and set it up. Since Firebase is a difficult tool, you can't really play around with it in the same Repository as the Freedom Project. So I started by creating a repository made just for tinkering. You can find this repository [here](https://github.com/evangelinae1225/firebase-tinker1). What I did so for in this Repository is set-up Webpack. The reason I needed to install it was that Webpack helps your browser read tons of separate files more efficiently, which is a great necessity when you have Firebase since it is separated into a lot of files. As well, I added the tool itself to my project. I installed Firebase 9 instead of the latest one because the tutorial I was using was from a couple of years ago. So I will be using slightly different syntax compared to modern Firebase. 


## Engineering Design Process

At the moment, I am at my first step of the Engineering Design Process. This is where I define the problem. There are many wishing simulators that are included in famous gacha games. Most of the time, they are rigged to get players to spend more in-game money to obtain the character they want. So, my partner and I decided to create a wishing Simulator where the games aren't rigged, and you actually have a great chance of obtaining the character you want!
